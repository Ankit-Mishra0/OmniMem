Every new tool starts by asking
what you're building.

OmniMem answers for you. It keeps one brief per project on your own machine and hands it to whichever tool you open next — so you explain the work once, not once per window.

Works today with Claude Code, Codex, Cursor, Antigravity, Windsurf, Gemini CLI, Zed and VS Code — plus ChatGPT, Claude.ai and Gemini in the browser.

the tax

Four tools, one project, the same paragraph every time.

claude code So I'm building a memory layer, it's Python, SQLite, no…

codex So I'm building a memory layer, it's Python, SQLite, no…

antigravity So I'm building a memory layer, it's Python, SQLite…

chatgpt So I'm building a memory layer, it's Pyth…

Each tool is capable. None of them knows what the last one decided. So you re-describe the goal, re-list the constraints, and re-explain the bug you already fixed — and the tool still re-litigates a decision you settled on Tuesday.

OmniMem writes it down once, in a folder you own, and gives every tool the same starting point.

Facts are typed, so the brief stays short and the important things survive: goal decision constraint convention stack entity gotcha task open question

the loop

Capture, store, resume.

capture

It notices while you work

In Claude Code, session hooks record what you asked for and what came back — no tool call, no cooperation needed. Other editors get a rules file that tells the agent to save what it establishes. In the browser, the extension reads the conversation you're already having.

Nothing is summarised by a paid API. The model you're already talking to does it.

store

One folder per project

Claims are deduplicated, typed and scored, then rendered into plain markdown you can read and edit: PROJECT.md, DECISIONS.md, TASKS.md, HANDOFF.md. Anything you put in PINNED.md is passed through untouched and outranks everything the machine guessed.

SQLite is an index over those files, not a place your work gets locked into.

resume

The next tool starts informed

Open any connected tool and say “continue.” It reads the brief first: the goal, the decisions in force, the constraints, the gotchas, and the one sentence describing where the last session stopped.

In the browser, one click puts the brief in the message box.

by hand

If you'd rather paste the config yourself

Replace /path/to/python with your virtualenv's interpreter and /path/to/OmniMem with the checkout. The installer fills both in for you — this is only here for the cases it can't reach, like a remote machine.

Claude Code — ~/.claude.json and ~/.claude/settings.json

The MCP server:

{
  "mcpServers": {
    "omnimem": {
      "command": "/path/to/python",
      "args": ["-m", "omnimem.cli", "mcp"],
      "env": { "PYTHONPATH": "/path/to/OmniMem" }
    }
  }
}

Claude Code is the one host that needs no cooperation from the model, because hooks can print context directly into the session. Add these to ~/.claude/settings.json: 

{
  "hooks": {
    "SessionStart": [
      { "matcher": "startup|resume|clear",
        "hooks": [{ "type": "command", "timeout": 15,
          "command": "PYTHONPATH=/path/to/OmniMem /path/to/python -m omnimem.cli hook session_start" }] }
    ],
    "UserPromptSubmit": [
      { "hooks": [{ "type": "command", "timeout": 30,
          "command": "PYTHONPATH=/path/to/OmniMem /path/to/python -m omnimem.cli hook user_prompt" }] }
    ],
    "Stop": [
      { "hooks": [{ "type": "command", "timeout": 15,
          "command": "PYTHONPATH=/path/to/OmniMem /path/to/python -m omnimem.cli hook stop" }] }
    ]
  }
}

The capture hooks always exit 0, on purpose. A non-zero exit from Stop tells Claude Code not to stop — a memory bug must never be able to wedge a coding session.

Antigravity & Gemini CLI — ~/.gemini/settings.json

Same mcpServers block as Claude Code. Then, so the agent actually reaches for it, append the rules block to ~/.gemini/GEMINI.md:

## OmniMem — cross-tool project memory

1. At the start of every session, call `omnimem_resume` before anything else.
2. When a decision is made, call `omnimem_add_decision` immediately.
3. Before the session ends, call `omnimem_save_session` with `facts`
   ([{kind, text}], one atomic claim each) and `next_step`.
4. Use `omnimem_search` instead of asking the user about earlier work.

Antigravity keeps its own knowledge store per workspace. OmniMem doesn't replace it — it's the layer that survives leaving Antigravity.

Codex CLI — ~/.codex/config.toml 
[mcp_servers.omnimem]
command = "/path/to/python"
args = ["-m", "omnimem.cli", "mcp"]
startup_timeout_sec = 20

[mcp_servers.omnimem.env]
PYTHONPATH = "/path/to/OmniMem"

Put the same rules block in ~/.codex/AGENTS.md. Note the snake_case keys and the mcp_servers spelling — TOML, not JSON.

Cursor — ~/.cursor/mcp.json and a rule file

Standard mcpServers block. The rule goes in ~/.cursor/rules/omnimem.mdc and must start with this front matter, or Cursor never applies it:

---
description: Cross-tool project memory via OmniMem
alwaysApply: true
---
VS Code and Zed — the key name changes

This is the usual reason a server silently fails to appear. VS Code (.vscode/mcp.json) uses servers. Zed (~/.config/zed/settings.json) uses context_servers. Everyone else uses mcpServers. 

// .vscode/mcp.json
{ "servers": { "omnimem": { "command": "/path/to/python",
  "args": ["-m", "omnimem.cli", "mcp"],
  "env": { "PYTHONPATH": "/path/to/OmniMem" } } } }
Browser — ChatGPT, Claude.ai, Gemini and six more
  1. Start the engine: python -m omnimem.cli serve
  2. Open chrome://extensions and turn on Developer mode.
  3. Load unpacked → pick the extension/ folder.
  4. Open a chat. A small bar appears bottom-right: an indigo dot means it's watching, Inject brief pastes the project state into the message box.

The extension talks only to 127.0.0.1 and fetches its access token from the engine on first run. Capture is on by default; pause it globally or per site from the toolbar popup.

privacy

No account, no server, no API key.

It all lives in one folder

~/.omnimem/ — a SQLite file and plain markdown. Delete a project folder and that memory is gone. Nothing syncs anywhere.

The port is closed to the web

The engine binds 127.0.0.1 only, allows a fixed list of chat origins, and requires a token from ~/.omnimem/token on every write. A page you visit can't read your memory.

Secrets are stripped in the page

API keys, GitHub and Slack tokens, JWTs, database URLs with passwords, and email addresses are replaced before the text leaves the tab — not after it arrives.

This page proves the point

It loads no fonts, scripts, or trackers from anywhere. Served straight off the engine on your own machine. View source.

install

Four commands.

  1. Set up the environment.

    python3 -m venv .venv && .venv/bin/pip install -r requirements.txt

  2. Make the command short. Add this to your shell profile.

    alias omnimem="$(pwd)/.venv/bin/python -m omnimem.cli"

  3. Wire up every tool it can find.

    omnimem install --all

  4. Start the engine. Leave it running; it idles at about 0% CPU.

    omnimem serve

Then check it: omnimem doctor lists every tool it's connected to and what's missing. omnimem resume prints the brief for the folder you're standing in.

The test that matters: describe a task in Claude Code, then open ChatGPT and say “continue.” If it knows the project, it works.

questions

Reasonable doubts

Does it cost anything to run?

No. There is no hosted service and no API key. Summaries come from the model you're already talking to, so the marginal cost of remembering is zero.

Does it need a GPU, or download a model?

Neither. Deduplication is token-set overlap and content hashing; search is SQLite FTS5. It runs in roughly 60–90 MB of RAM on a laptop and does nothing while idle. A local embedding model is an optional extra, not the default path.

What happens when the engine isn't running?

Editors write to SQLite directly, so saving still works with the server off. The browser extension queues what it captured and syncs when the engine comes back. Nothing raises an error at the model — a tool that errors once gets ignored for the rest of a session, which is the worst possible failure for a memory tool.

Does it read my whole codebase?

No. It reads manifests — requirements.txt, package.json, pyproject.toml, go.mod, Dockerfile — to work out your stack, and it checks that a file path mentioned in conversation actually exists before recording it. Source files are never opened or stored.

How do I see or fix what it thinks?

Open ~/.omnimem/projects/<project>/PROJECT.md. It's generated, so edits there get overwritten — put corrections in PINNED.md in the same folder and they'll be passed through verbatim and outrank everything else. Tick a checkbox in TASKS.md and it's marked done.

Can I run it on a server instead of my laptop?

Yes, and you don't need to. If you want to anyway, any always-free small VM works — Oracle Cloud's free ARM tier, or a GitHub Codespace for a few hours. Put it behind an SSH tunnel rather than exposing the port; the security model assumes a machine only you can reach. Don't put ~/.omnimem on Dropbox, iCloud or Google Drive — a synced SQLite write-ahead log corrupts, and the engine refuses to start if it detects one.

Is this finished?

No — it's a working prototype, used daily by its author. Contradictory decisions can both appear in a brief until supersession rules land, and the browser selectors will break whenever a chat site reships its markup. Every site's selectors live in one file, extension/platforms.js, for exactly that reason.
